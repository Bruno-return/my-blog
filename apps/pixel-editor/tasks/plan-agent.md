# Plan 서브에이전트 지침 — pixel-editor

## 역할
너는 계획(Plan) 담당이다. 코드는 쓰지 않는다. 계획 문서 하나만 만든다.

## 만들 웹앱
사용자 요청: "픽셀 아트 에디터. 16×16 격자에 도트를 찍어서 그림을 그리고, 완성하면 PNG로 저장. 색상 팔레트 포함."

반드시 들어갈 것:
- 16×16 격자 캔버스. 클릭/탭으로 한 칸 칠하기, 누른 채 드래그로 연속 칠하기(마우스·터치·펜 모두).
- 색상 팔레트: 기본 색 여러 개 + 사용자 지정 색(`<input type="color">`) 선택. 현재 색 표시.
- 지우개(투명), 전체 지우기.
- PNG 저장: 투명 배경 유지. 16×16 원본은 너무 작으므로 배율(예: 1×, 8×, 16×, 32×) 선택 또는 적절한 기본 배율을 제안. 이미지 스무딩 없이 또렷하게.

있으면 좋은 것(범위를 정해서 spec에 넣거나 범위 밖으로 명시):
- 되돌리기/다시 실행, 채우기(flood fill), 스포이트, 격자선 표시 토글, 작업 자동 저장(localStorage)

## 프로젝트 규칙 (반드시 반영)
- 순수 HTML/CSS/JavaScript(ES 모듈). 빌드 도구·npm 없음. 외부 라이브러리는 최소화(가능하면 없음, CDN은 허용되나 필요성을 설명).
- 모든 파일은 `apps/pixel-editor/` 안에서 자체 완결. 블로그의 다른 파일은 참조·수정하지 않는다. 경로는 `./` 상대 경로.
- 모바일 우선: 375px 폭에서 가로 스크롤 없음, 터치로 그릴 때 페이지가 스크롤/확대되지 않게(`touch-action`), 터치 대상 44px 이상.
- 라이트/다크 모드: `prefers-color-scheme`. UI 색상은 CSS 변수로만 정의(팔레트의 그림 색상 값은 데이터이므로 JS에 있어도 됨).
- 블로그 메인 페이지에 iframe 카드(높이 약 600px, 폭은 모바일 기준 약 310px~)로 들어간다. 그 크기에서도 쓸 만하게 배치를 고려한다. iframe 안에서 로드 시 포커스를 빼앗지 않는다.
- iframe 안에서도 PNG 다운로드가 동작하는지 고려한다(`<a download>` + `canvas.toBlob`). 
- 접근성: 버튼 레이블, 팔레트 색에 이름(aria-label), 선택 상태(`aria-pressed`), `:focus-visible` 유지. 키보드만으로 그리는 기능은 선택 사항.
- 코딩 컨벤션: `const`/`let`, ES 모듈, 세미콜론, 2칸 들여쓰기, 작은따옴표, 전역 변수 없음.
- 로컬 실행: 저장소 루트에서 `node serve.mjs` → `http://localhost:8000/apps/pixel-editor/`.
- 참고: 같은 저장소의 `apps/double-tiles/spec.md`가 이전 앱의 계획서다. 형식 참고만 하고 내용은 베끼지 않는다.

## 산출물
`apps/pixel-editor/spec.md` 하나(한국어). 다음 내용을 담는다.
1. 개요와 기능 목록(필수/선택 구분)
2. 화면 구성 — 텍스트 와이어프레임(모바일, 데스크톱, iframe 크기)
3. 도구별 동작 정의(칠하기, 드래그 보간 — 빠르게 움직여도 칸이 비지 않게, 지우개, 전체 지우기, 그 밖에 넣기로 한 도구)
4. 팔레트 구성(기본 색 목록과 이름)
5. 데이터 모델(16×16 픽셀 배열 형식, 투명 표현)
6. PNG 내보내기 방법(배율, 스무딩 끄기, 파일 이름)
7. 디자인(CSS 변수 목록 라이트/다크, 격자의 투명 칸 표시 방법 등)
8. 파일 구조와 각 파일의 책임, 내보낼 함수 이름
9. 상태 저장(넣는다면 키 이름과 검증)
10. 테스트 체크리스트(Review 단계용)
11. 범위 밖

## 금지
- `apps/pixel-editor/spec.md` 외의 파일을 만들거나 수정하지 않는다. 이 지침 파일도 수정하지 않는다.
- 작업이 끝나면 spec.md 요약(10줄 이내)과, 사용자가 결정해야 할 선택지가 있으면 그것을 보고한다.
