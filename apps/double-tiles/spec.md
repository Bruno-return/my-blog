# Double Tiles (더블 타일) — 기획서 (spec.md)

> 위치: `apps/double-tiles/` · 순수 HTML/CSS/JavaScript(ES 모듈) · 빌드 도구/npm/외부 라이브러리 없음
> 로컬 실행: 저장소 루트에서 `node serve.mjs` → `http://localhost:8000/apps/double-tiles/`

## 1. 개요와 게임 규칙

### 1.1 개요
4×4 격자 위의 숫자 타일을 한 방향으로 밀어, 같은 숫자끼리 합치며 점수를 쌓는 퍼즐 게임이다. 끝은 정해져 있지 않다. 단계별 목표 타일을 하나씩 깨면서 최고 점수를 노린다(2절).

### 1.2 시작 상태
- 4×4 빈 격자에 무작위 빈 칸 2곳에 타일을 하나씩 놓는다.
- 새 타일의 값은 90% 확률로 `2`, 10% 확률로 `4`이다.
- 점수는 0, 현재 목표 타일은 `64`(1단계)이다.

### 1.3 이동 규칙 (정확한 정의)
방향 `left | right | up | down` 중 하나를 입력하면 격자의 줄(가로 4줄 또는 세로 4줄)을 각각 따로 처리한다. 줄 하나는 다음 순서로 처리한다.

1. **선두 방향 정하기**: 이동 방향 쪽 끝이 선두다(left면 왼쪽 끝, down이면 아래 끝).
2. **압축**: 빈 칸을 없애고 타일을 선두 쪽으로 모은다. 순서는 바꾸지 않는다.
3. **합치기**: 선두부터 차례로 보며, 이웃한 두 타일의 값이 같으면 하나로 합친다(값 ×2). 합쳐 만든 타일은 **이번 이동에서는 다시 합쳐지지 않는다.** 합친 다음에는 그 다음 타일부터 이어서 본다.
4. **다시 압축**: 합치느라 생긴 빈 칸을 메운다.

예시(left, 왼쪽이 선두):

| 이동 전 | 이동 후 | 설명 |
|---|---|---|
| `2 2 2 2` | `4 4 . .` | 두 쌍이 따로 합쳐지고, 4끼리는 다시 합쳐지지 않음 |
| `2 2 4 .` | `4 4 . .` | 새로 만든 4는 원래 있던 4와 합쳐지지 않음 |
| `4 4 8 .` | `8 8 . .` | 같은 이유 |
| `2 . 2 2` | `4 2 . .` | 선두 쪽 쌍이 먼저 합쳐짐 |
| `2 4 2 4` | `2 4 2 4` | 변화 없음 |
| `8 . . 8` | `16 . . .` | 빈 칸을 건너 합쳐짐 |

- right/down은 선두가 반대쪽일 뿐 규칙은 같다(예: right에서 `2 2 2 .` → `. . 2 4`).

### 1.4 점수
- 합쳐서 생긴 타일 값만큼 점수가 오른다(예: 8+8 → 16이면 +16).
- 한 번에 여러 쌍이 합쳐지면 모두 더한다(`2 2 2 2` left → +8).

### 1.5 새 타일 생성
- 이동으로 격자가 **실제로 바뀐 경우에만** 빈 칸 하나에 새 타일(2: 90%, 4: 10%)을 무작위로 놓는다.
- 아무 타일도 움직이지 않았다면(무효 이동) 새 타일도 점수 변화도 없다. 입력은 그냥 무시한다.

### 1.6 게임 오버 판정
새 타일을 놓은 뒤 아래 두 조건을 **모두** 만족하면 게임 오버다.
- 빈 칸이 없다.
- 가로나 세로로 이웃한 두 칸의 값이 같은 곳이 하나도 없다.

## 2. 목표 / 종료 조건

### 2.1 독자적 목표: "단계 목표(스테이지 타깃)" + 끝없는 진행
- 고정된 승리 타일이나 승리 화면은 **없다.**
- 화면 위쪽에 **"다음 목표"** 배지로 현재 목표 타일을 보여 준다. 1단계 목표는 `64`이다.
- 격자에 목표 값 이상인 타일이 생기면 그 단계를 깬 것이다.
  - 단계 번호 +1, 목표 값 ×2 (64 → 128 → 256 → 512 → …, 끝 없음)
  - 배지가 잠깐 빛나는 효과(0.6초)를 내고 `aria-live`로 "3단계 달성! 다음 목표 512"처럼 알린다.
  - 한 번에 여러 단계를 넘으면(이론상) 도달한 최고 타일보다 큰 첫 목표까지 한꺼번에 올린다.
- 게임 오버가 될 때까지 계속한다. 끝나면 최종 점수, 도달한 단계, 최고 타일을 보여 준다.

### 2.2 이렇게 정한 이유
- **원작과 구별**: "특정 타일을 만들면 승리"라는 고정 목표를 쓰지 않으므로 원작의 핵심 문구나 목표와 겹치지 않는다.
- **짧은 성취감**: 블로그 iframe 카드나 모바일처럼 짧게 플레이하는 환경에서도 64·128처럼 금방 닿는 목표가 있어 동기가 생긴다.
- **끝없는 경쟁**: 승리로 끝나지 않으므로 최고 점수와 최고 단계 경쟁으로 이어진다.
- **구현 단순화**: "승리 후 계속하기" 같은 분기가 필요 없다.

### 2.3 종료 조건
- 1.6의 조건을 만족하면 게임 오버다. 게임 오버 안내 위에 다시 시작 버튼을 띄운다.
- "새 게임" 버튼을 누르면 언제든 즉시 새 게임을 시작한다(확인 대화상자 없음, 9절 참고).

### 3.3 레이아웃 규칙
- 전체 폭: `max-width: 480px`, 가운데 정렬, 좌우 여백 16px. 375px 폭에서 가로 스크롤이 없어야 한다.
- 격자: `width: min(100%, 420px); aspect-ratio: 1;`, 칸 간격 `clamp(6px, 2.5vw, 12px)`.
- 타일 글자 크기는 자릿수에 따라 줄인다(`data-digits` 속성: 1~2자리 큼, 3자리 중간, 4자리 작음, 5자리 이상 더 작음). `clamp()`와 컨테이너 기준 단위(`cqw`)를 쓰고, 지원하지 않는 환경을 위해 `vw` 값을 대체값으로 둔다.
- iframe 카드처럼 높이가 낮은 곳(예: 높이 520px 이하)에서는 부제와 안내 문구를 숨기고(`@media (max-height: 560px)`) 격자가 보이도록 한다.

## 4. 색상·디자인 방향

### 4.1 콘셉트: "심해에서 오로라로" (Deep Sea → Aurora)
- 원작의 베이지/주황 계열은 쓰지 않는다. 값이 커질수록 **청록 → 파랑 → 남색 → 보라 → 자홍**으로 차갑게 깊어지다가 마지막에 빛나는 색으로 바뀐다.
- 모서리는 둥글게(`--radius: 12px`, 타일 `10px`), 그림자는 거의 쓰지 않는다. 깔끔한 플랫 스타일이다.
- 글꼴은 시스템 글꼴 스택을 쓰고(`system-ui, -apple-system, 'Segoe UI', 'Noto Sans KR', sans-serif`) 숫자에는 `font-variant-numeric: tabular-nums`를 준다. 웹폰트는 쓰지 않는다.
- 색상은 **오직 CSS 변수로만** 정의한다. `:root`에 라이트 값을 두고 `@media (prefers-color-scheme: dark)`에서 다시 정의한다. JS에서는 색상 값을 쓰지 않고 `data-level` 속성만 바꾼다.
- 대비 기준: 일반 UI 글자는 배경 대비 4.5:1 이상. 타일 숫자는 굵고 큰 글자이므로 3:1 이상.

## 5. 조작

### 5.1 키보드
| 키 | 동작 |
|---|---|
| `ArrowLeft/Right/Up/Down` | 해당 방향 이동 |
| `a/d/w/s` (`A/D/W/S` 포함) | 각각 왼쪽/오른쪽/위/아래 이동 |
| `Tab` | 기본 포커스 이동(막지 않음) |
| `Enter`/`Space` | 포커스된 버튼 실행(기본 동작) |

- 리스너는 `document`의 `keydown` 하나만 둔다(`ui.js`).
- `ctrlKey`, `metaKey`, `altKey` 중 하나라도 눌려 있으면 무시한다(브라우저 단축키 보호).
- `e.target`이 `input`이나 `textarea`이면 무시한다(지금은 없지만 미래를 위한 방어).
- 게임 오버 오버레이가 열려 있으면 이동 키는 무시하되, 스크롤을 막기 위해 `preventDefault()`는 호출한다.
- `e.repeat`(키를 누르고 있어 반복 입력되는 경우)도 이동으로 처리한다. 애니메이션은 상태를 막지 않으며, 새 입력이 오면 바로 최종 위치로 다시 그린다.

### 5.2 터치 스와이프
- Pointer Events(`pointerdown` / `pointerup` / `pointercancel`)를 격자 요소에 붙이고, `e.pointerType`이 `touch`나 `pen`일 때만 스와이프로 처리한다. 마우스 드래그도 허용해도 된다(선택).
- 판정: 시작점과 끝점의 차이 `dx`, `dy`에서 `max(|dx|, |dy|) >= 30px`이면 두 값 중 큰 쪽의 축과 부호로 방향을 정한다. 30px 미만은 무시한다.
- 격자에 `touch-action: none`을 주어 스와이프할 때 페이지 스크롤이나 당겨서 새로고침이 일어나지 않게 한다. 격자 밖에서는 일반 스크롤이 된다.
- 한 번의 스와이프는 한 번의 이동이다.

### 5.3 기본 스크롤 방지 (iframe 포함)
1. **처리한 키만 막기**: 이동 키(방향키, WASD)를 처리할 때 `e.preventDefault()`를 호출한다. 이렇게 하면 iframe 안 문서가 스크롤되지 않고, 스크롤이 부모 페이지로 이어지는 것(scroll chaining)도 막는다. 다른 키는 건드리지 않는다.
2. **문서 넘침 방지**: `html, body { overscroll-behavior: contain; }`. 레이아웃이 화면 안에 들어가도록 설계해 iframe 안에서 스크롤할 내용이 거의 없게 한다(높이가 모자라면 세로 스크롤은 허용, 가로 넘침은 금지).
3. **포커스 정책**: 페이지 로드 시 `autofocus`나 `focus()`를 **쓰지 않는다.** iframe이 부모 페이지의 포커스를 빼앗지 않게 하기 위해서다. 사용자가 격자를 클릭하거나 탭하면(`pointerdown`) 격자에 `focus({ preventScroll: true })`를 준다. 그 뒤 키 입력이 iframe 문서로 들어온다.
4. **안내**: iframe 안에서 아직 포커스가 없을 때를 위해 조작 안내에 "격자를 한 번 누르면 키보드로 조작할 수 있어요"를 넣는다.
5. 격자에 포커스가 있을 때 `:focus-visible` 외곽선(`outline: 3px solid var(--focus); outline-offset: 3px`)을 보여 준다.

```
apps/double-tiles/

├── storage.js      # localStorage 읽기/쓰기 (예외 처리 포함)

├── spec.md         # 이 문서
```

### 6.1 `index.html`
- `<html lang="ko">`, `<meta charset="utf-8">`, `<meta name="viewport" content="width=device-width, initial-scale=1">`, `<meta name="color-scheme" content="light dark">`, `<title>Double Tiles</title>`.
- `<link rel="stylesheet" href="./style.css">`, `<script type="module" src="./ui.js"></script>`.
- 3.2의 요소를 정적 마크업으로 둔다. 배경 칸 16개는 HTML에 직접 쓰거나 `ui.js`에서 만든다(둘 중 하나로 통일).
- 블로그 경로(`/css`, `/js` 등)는 참조하지 않는다. 모든 경로는 `./`로 시작하는 상대 경로다.

### 6.2 `game.js` — 순수 로직 (테스트 가능하게)
- DOM, `window`, `localStorage`를 쓰지 않는다. 난수는 매개변수 `rng`(기본값 `Math.random`)로 받아 결과를 재현할 수 있게 한다.
- 상태는 **불변 객체**로 다룬다. 함수는 새 상태를 돌려준다.
- 데이터 모델:
  ```
  Tile  = { id: number, value: number }
  State = {
    size: 4,
    grid: (Tile | null)[][],   // grid[row][col]
    score: number,
    stage: number,             // 1부터
    target: number,            // 64부터
    maxTile: number,
    over: boolean,
    nextId: number
  }
  ```
- 내보낼 함수(이름 고정):
  - `export const SIZE = 4;`
  - `export function createGame(rng = Math.random)` → 타일 2개가 놓인 새 상태
  - `export function move(state, direction, rng = Math.random)` → `{ state, moved, gained, merged: [{ id, value, from: [idA, idB] }], spawned: Tile | null, stageUp: number }` (`stageUp`은 이번에 오른 단계 수)
  - `export function slideLine(line)` → `{ line, gained, merges }` (줄 하나를 선두 방향 기준으로 처리하는 핵심 함수, 1.3절 표가 단위 테스트 기준)
  - `export function canMove(state)` → boolean
  - `export function addRandomTile(state, rng)` → 새 상태
  - `export function serialize(state)` / `export function deserialize(obj)` → 저장용 일반 객체 변환과 검증(잘못된 데이터면 `null`)
- 방향 처리: 줄을 꺼내 선두가 앞에 오도록 정렬하고 → `slideLine` → 원래 위치에 되돌려 놓는다. 회전 행렬을 써도 되지만 줄 추출/복원 방식을 권장한다(읽기 쉬움).
- 합쳐진 타일은 새 `id`를 받는다(UI가 합치기 효과를 줄 수 있게). 움직이기만 한 타일은 원래 `id`를 유지한다.

### 6.3 `storage.js`
- 키 이름: `double-tiles:best`(숫자), `double-tiles:game`(JSON).
- `loadBest()`, `saveBest(n)`, `loadGame()`, `saveGame(obj)`, `clearGame()`.
- 모든 접근을 `try/catch`로 감싼다. sandbox iframe이나 사생활 보호 모드에서 `localStorage`를 쓸 수 없으면 조용히 메모리 동작으로 넘어간다(오류를 던지지 않음).

### 6.4 `ui.js` — 렌더링과 입력 (진입점)
- 모듈 안 지역 상수/변수만 쓴다. 전역(`window.*`)에 아무것도 붙이지 않는다.
- 책임:
  - 시작 시 `loadGame()` → `deserialize`가 성공하고 `over === false`이면 이어하기, 아니면 `createGame()`.
  - `render(state, result)`: 타일 DOM을 `id`로 재사용·추가·삭제한다. 각 타일에 `data-level`, `data-digits`, 위치용 CSS 변수(`--row`, `--col`)를 준다. 새 타일에는 `is-new`, 합쳐진 타일에는 `is-merged` 클래스를 잠깐 붙인다.
  - 점수판 갱신, 최고 점수 갱신(`score > best`이면 바로 저장).
  - 입력: 5절의 키보드·스와이프 처리 → `move()` 호출 → `moved`가 참일 때만 렌더링, 저장, 알림.
  - 알림(aria-live):
    - `#sr-status`(polite): 점수가 오른 이동에서 "점수 1,240, 16 획득"처럼 알린다. 연속 입력으로 알림이 넘치지 않도록 마지막 알림 뒤 400ms 디바운스한다.
    - 단계 달성: "2단계 달성! 다음 목표 128".
    - `#sr-alert`(assertive): "게임 오버. 최종 점수 1,240, 3단계"
  - 게임 오버 시 오버레이를 열고 "다시 시작" 버튼에 포커스를 준다. 새 게임을 시작하면 오버레이를 닫고 격자에 포커스를 돌려준다.
  - 매 이동 뒤 `saveGame(serialize(state))`. 게임 오버면 `clearGame()`.

### 6.5 `style.css`
- 4절의 변수 전체, 레이아웃(3.3), 타일 위치 계산: `transform: translate(calc(var(--col) * (100% + var(--gap))), calc(var(--row) * (100% + var(--gap))))`.
- `.visually-hidden` 유틸리티, `:focus-visible` 스타일, 버튼 최소 크기 `min-height: 44px; min-width: 44px`.
- `prefers-color-scheme`, `prefers-reduced-motion`, 낮은 높이용 미디어 쿼리.

### 6.6 코딩 컨벤션
`const`/`let`만 사용(`var` 금지), ES 모듈(`import`/`export`), 세미콜론 필수, 2칸 들여쓰기, 작은따옴표, 전역 변수 없음, 외부 라이브러리 없음.

## 7. 상태 저장

| 키 | 값 | 저장 시점 | 읽는 시점 |
|---|---|---|---|
| `double-tiles:best` | 최고 점수(정수 문자열) | 점수가 최고 점수를 넘을 때마다 | 페이지 로드 |
| `double-tiles:game` | `serialize(state)` JSON | 유효한 이동마다, 새 게임 시작 시 | 페이지 로드(이어하기) |

- **이어하기(포함)**: 새로고침하거나 다시 방문해도 진행 중이던 판을 그대로 복원한다. 게임 오버 상태는 저장하지 않는다(`clearGame()`).
- 복원 검증: `size === 4`, `grid`가 4×4이고 각 칸이 `null`이거나 값이 2 이상의 2의 거듭제곱, `score`가 0 이상의 정수인지 확인한다. 하나라도 틀리면 버리고 새 게임을 시작한다.
- 최고 점수 값이 숫자가 아니거나 음수면 0으로 본다.
- 블로그의 다른 앱과 키가 겹치지 않도록 `double-tiles:` 접두사를 쓴다.

## 8. 테스트 체크리스트 (Review 단계용)

### 8.1 로직 (`game.js`, 브라우저 콘솔이나 임시 테스트 페이지에서 `slideLine` 확인)
- [ ] 1.3절 표의 6가지 예시가 모두 기대 결과와 같다.
- [ ] `2 2 2 2` → `4 4 . .`이고 점수 +8 (한 번 합쳐진 타일은 다시 합쳐지지 않음).
- [ ] right/up/down에서도 선두 방향이 맞다(예: right `2 2 2 .` → `. . 2 4`).
- [ ] 무효 이동이면 `moved === false`, 새 타일 없음, 점수 변화 없음.
- [ ] 유효 이동마다 새 타일이 정확히 1개 생기고 값은 2 또는 4.
- [ ] 꽉 찬 격자에 합칠 쌍이 없으면 `over === true`, 합칠 쌍이 하나라도 있으면 `false`.
- [ ] 64를 만들면 단계 2, 목표 128로 바뀐다.
- [ ] 같은 `rng`를 주면 결과가 똑같다(재현성).

### 8.2 UI / 입력
- [ ] 방향키와 WASD로 네 방향 모두 이동한다. Ctrl/Cmd를 함께 누르면 이동하지 않는다.
- [ ] 이동 키를 눌러도 페이지가 스크롤되지 않는다(일반 페이지와, 높이를 작게 준 iframe에 넣은 경우 모두).
- [ ] 페이지 로드 시 iframe이 부모 페이지의 포커스를 빼앗지 않는다. 격자를 클릭하면 키보드 조작이 된다.
- [ ] 모바일(개발자 도구 375px, 터치 에뮬레이션)에서 스와이프 네 방향이 동작하고, 30px 미만의 짧은 터치는 무시된다.
- [ ] 격자에서 스와이프할 때 페이지가 스크롤되거나 새로고침되지 않는다.
- [ ] "새 게임"을 누르면 점수 0, 타일 2개, 1단계로 초기화된다.
- [ ] 게임 오버 오버레이가 뜨고 "다시 시작"에 포커스가 가며, 누르면 새 게임이 시작된다.
- [ ] 5자리 값(예: 16384, 콘솔로 상태 주입)도 타일 밖으로 넘치지 않는다.

### 8.3 레이아웃 / 디자인
- [ ] 375px 폭에서 가로 스크롤이 없다(`document.documentElement.scrollWidth <= 375`).
- [ ] 모든 버튼이 44×44px 이상이다.
- [ ] 라이트/다크 모드가 OS 설정을 따르고, 두 모드에서 글자가 잘 읽힌다.
- [ ] CSS 안의 색상 값은 변수 정의 부분에만 있다(규칙 안에 직접 쓴 색상 없음).
- [ ] "2048"이라는 이름, 원작 문구, 베이지/주황 팔레트를 쓰지 않았다.
- [ ] `prefers-reduced-motion: reduce`에서 애니메이션이 꺼진다.

### 8.4 접근성
- [ ] 점수가 오르면 `#sr-status`의 텍스트가 바뀐다(스크린 리더나 DOM으로 확인).
- [ ] 단계 달성과 게임 오버가 `aria-live`로 알려진다.
- [ ] 모든 버튼에 보이는 텍스트나 `aria-label`이 있다.
- [ ] 키보드 포커스에 `:focus-visible` 외곽선이 보인다(`outline: none`만 쓰고 대체 스타일이 없는 곳이 없다).

### 8.5 저장
- [ ] 최고 점수가 새로고침 뒤에도 남아 있다.
- [ ] 진행 중이던 판이 새로고침 뒤에 그대로 이어진다.
- [ ] `localStorage`에 잘못된 JSON을 넣어도 오류 없이 새 게임이 시작된다.
- [ ] `localStorage` 접근이 막힌 환경(sandbox iframe)에서도 게임이 동작한다.

### 8.6 코드 품질 / 규칙
- [ ] 콘솔 오류나 경고가 없다.
- [ ] `var`, 전역 변수, 외부 라이브러리, 빌드 도구가 없다. 세미콜론, 2칸 들여쓰기, 작은따옴표를 지켰다.
- [ ] `apps/double-tiles/` 밖의 파일을 참조하거나 수정하지 않았다.
- [ ] `game.js`에 DOM이나 `localStorage` 접근이 없다.
