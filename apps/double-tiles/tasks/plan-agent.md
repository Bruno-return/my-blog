# Plan 서브에이전트 지침 — double-tiles

## 역할
너는 계획(Plan) 담당이다. 코드는 쓰지 않는다. 계획 문서 하나만 만든다.

## 만들 웹앱
사용자 요청: "방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임, 점수판 포함."

- 4×4 격자에서 방향키(모바일은 스와이프)로 모든 타일을 한쪽으로 민다.
- 같은 숫자 타일이 부딪히면 하나로 합쳐지고 값이 두 배가 된다. 합쳐진 값만큼 점수가 오른다.
- 한 번 밀 때마다 빈 칸에 새 타일(2, 가끔 4)이 하나 생긴다.
- 더 이상 움직일 수 없으면 게임 오버.
- 점수판: 현재 점수, 최고 점수(localStorage 저장).

## 중요한 제약 — 독자적인 게임으로 설계
이 메커니즘은 유명 게임 "2048"과 같은 장르지만, 그 게임을 그대로 베끼면 안 된다.
- 게임 이름은 **Double Tiles (더블 타일)** 로 한다. "2048"이라는 이름을 쓰지 않는다.
- 2048 특유의 베이지/주황 색상표, 레이아웃, 문구("Join the numbers and get to the 2048 tile!" 등)를 쓰지 않는다. 독자적인 색상과 디자인을 제안한다.
- "2048 타일을 만들면 승리" 같은 고정 목표 대신 독자적 목표를 정한다(예: 끝없이 진행하며 최고 기록 경쟁, 또는 단계별 목표 타일 표시 등). spec에 근거를 적는다.

## 프로젝트 규칙 (반드시 반영)
- 순수 HTML/CSS/JavaScript. 빌드 도구·npm 없음. 외부 라이브러리는 최소화(필요 없으면 쓰지 않는다).
- 모든 파일은 `apps/double-tiles/` 안에서 자체 완결. 블로그의 다른 파일(index.html, css/, js/, posts/)은 참조·수정하지 않는다.
- 모바일 우선: 375px 폭에서 가로 스크롤 없음, 터치 스와이프 지원, 터치 대상 44px 이상.
- 라이트/다크 모드: `prefers-color-scheme`를 따른다. 색상은 CSS 변수로만 정의한다.
- 블로그 index.html에 iframe 카드로 들어갈 예정이므로, iframe 안에서도 방향키가 페이지 스크롤을 일으키지 않게 하는 방법을 고려한다.
- 접근성: 점수 변화·게임 오버를 `aria-live`로 알리고, 버튼에 레이블, `:focus-visible` 유지.
- 코딩 컨벤션: `const`/`let`, ES 모듈, 세미콜론, 2칸 들여쓰기, 작은따옴표, 전역 변수 없음.
- 로컬 실행: 저장소 루트에서 `node serve.mjs` → `http://localhost:8000/apps/double-tiles/`.

## 산출물
`apps/double-tiles/spec.md` 하나만 작성한다(한국어). 다음 내용을 담는다.
1. 개요와 게임 규칙(이동·합치기 규칙을 정확히: 한 번의 이동에서 이미 합쳐진 타일은 다시 합쳐지지 않음 등)
2. 목표/종료 조건
3. 화면 구성(점수판, 새 게임 버튼, 격자, 게임 오버 안내) — 간단한 텍스트 와이어프레임
4. 색상·디자인 방향(2048과 다른 독자적 팔레트, 라이트/다크 변수 목록)
5. 조작: 키보드(방향키, WASD 선택), 터치 스와이프, 기본 스크롤 방지 방법
6. 파일 구조와 각 파일의 책임 (예: index.html, style.css, game.js(순수 로직), ui.js(렌더링·입력))
7. 상태 저장(최고 점수, 선택: 진행 중 게임 이어하기)
8. 테스트 체크리스트(Review 단계에서 쓸 항목)
9. 범위 밖(이번에 하지 않을 것)
